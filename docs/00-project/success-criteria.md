# Success Criteria

The project is successful when:

1. frontend runs locally,
2. backend runs locally,
3. MySQL connection works locally,
4. frontend communicates with backend,
5. backend communicates with MySQL,
6. core assignment functionality passes tests,
7. frontend production build passes,
8. backend production build passes,
9. frontend is deployed,
10. backend is deployed,
11. deployed backend can access deployed MySQL,
12. deployed frontend can access deployed backend,
13. secrets are not committed,
14. fresh-clone setup instructions work,
15. another developer can diagnose common failures using repository documentation.

## Product-specific criteria

The final application must allow:

1. a user to register,
2. a registered user to log in,
3. the user to browse spaces,
4. the user to reserve an available space/time,
5. conflicting reservation attempts to be rejected,
6. the user to view their reservations,
7. the user to modify/cancel their reservations,
8. an administrator to manage spaces,
9. an administrator to view reservations.
